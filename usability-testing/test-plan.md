# Usability Testing Plan

## Project
Human-Computer Interaction — Smart Cafeteria

## Purpose
Evaluate whether intended users can understand and complete the key tasks in the Smart Cafeteria prototype with minimal confusion or assistance.

## Objectives
1. Evaluate navigation and information architecture.
2. Check whether labels, icons, buttons, and screen layouts are understandable.
3. Measure task completion, errors, hesitation, and assistance required.
4. Identify usability problems that should be addressed in the next design iteration.
5. Verify that important cafeteria functions can be discovered by first-time users.

## Participants
A minimum of five representative smartphone users will participate. Participants will be identified as T01–T05 in the records to protect privacy.

## Method
- Conduct individual usability sessions using the current prototype.
- Give participants realistic goals rather than instructions about which controls to press.
- Ask participants to think aloud where practical.
- Do not guide participants unless they are completely blocked.
- Record task completion, approximate time, errors, hesitation, questions, and comments.
- Ask short follow-up questions after the tasks.

## Data to Record
| Measure | Description |
|---|---|
| Task completion | Completed independently, completed with help, or failed |
| Time | Approximate time to complete the task |
| Errors | Wrong selections, dead ends, or misunderstood controls |
| Assistance | Whether the facilitator had to intervene |
| Observations | Confusion, hesitation, navigation patterns |
| Comments | Participant feedback and suggestions |

## Success Criteria
A key task is successful when a participant completes it independently and reaches the intended result without significant confusion.

The prototype should be revised when multiple participants experience the same issue, a participant cannot complete an important task, or an interface element is consistently misunderstood.

## Session Script
1. Explain that the prototype is being tested, not the participant.
2. Explain the think-aloud approach.
3. Present the tasks one at a time.
4. Observe without leading the participant.
5. Record evidence objectively.
6. Ask follow-up questions after all tasks.
7. Thank the participant.

## Ethical/Privacy Notes
Do not collect unnecessary personal information. Use tester IDs rather than names in the repository. Obtain participant permission before recording audio, video, or screenshots.
